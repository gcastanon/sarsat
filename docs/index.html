SarSat codebase guide

SarSat is a JAX environment where each agent is a satellite in low Earth orbit and the team works together to image ground targets. It follows the Jumanji API and trains with MAPX (recurrent IPPO and MAPPO). This page explains how the code is laid out, which data structures move through it, and how experiments, training and evaluation work.

Every file or line reference is a link. Use the switch in the sidebar to open links in your local checkout (the default when this page is opened from disk) or on GitHub. For status, see STATUS.md; for the reasoning behind each design choice, see DECISIONS.md.

1. Overview

The repository has three parts, and each depends only on the one before it:

1 · EnvironmentPackage sarsat/. Pure JAX: orbits, targets, sensor geometry, battery, reward. It has no learning code.
sarsat/
2 · Training integrationDirectory mapx_integration/. Launch scripts, plus an overlay of wrappers, networks and Hydra configs that is copied into a MAPX checkout.
mapx_integration/
3 · Experiments and reportsDirectory scripts/. Reference-policy baselines, scenario sweeps, viewer exports and the results deck.
scripts/

What the environment simulates

ConceptIn the code
Agents1 to 1000 satellites on fixed circular orbits (about 550 km altitude). They never manoeuvre. Positions come from closed-form equations, so there is no integrator (satellite_frames).
TimeEach step is 60 s. An episode lasts time_limit=180 steps (3 hours).
Action (per satellite)[incidence, squint, side, sense]: two continuous slots in [-1, 1] and two binary switches (_decode_pointing).
SensorA side-looking SAR: 20–45° incidence on either side of the ground track, ±25° squint, no view straight down (nadir), and a 4° × 4° rectangular beam.
BatterySensing costs 10% per step and 2% recharges every step, which sustains sensing on 20% of steps. The scenarios lower this rate.
TargetsFixed latitude/longitude points, 80% on land. Optional high-value hotspots and time-windowed events.
RewardShared by the team: the summed priority of every target newly caught in any beam. Each target pays once. Priorities sum to 1, so the episode return is the fraction of priority imaged, in [0, 1].

3. The environment family

Four environment classes share the same dynamics, action and reward. They differ only in what the agents observe and whether targets have time windows. Each subclass adds to its parent through small extension hooks and leaves the parent's behaviour intact.

ClassAddsUsed by
SarSatThe base dynamics. Its observation is egocentric: the nearest accessible targets over a short look-ahead, the nearest neighbouring satellites, and the satellite's own battery.python -m sarsat.evaluate, reference baselines, tests, the plain env=sarsat MAPX wrapper
CoopSarSatA MARL-oriented observation: ranked candidate beams with their value and contention (how many charged teammates could take the same target), a 16-step look-ahead over hotspot clusters, and a compact global_state for centralised critics. It also caches the geometry for the next step inside the state.MAPX training (env=sarsat_coop), eval_checkpoint.py
WindowedSarSatA target_window of shape (M, 2). A target counts as accessible only between its first and last step. Every hotspot cluster shares one window, so it behaves as a single event.Reference baselines on the events scenarios
WindowedCoopSarSatThe Coop observation with the cluster look-ahead limited to open windows, plus a ninth slot feature: the fraction of the target's window still open.MAPX training on sarsat-{200,500}sat-events
Why reset keys line up across classes. Every class builds its orbits and targets in _initial_state with the same key splits. WindowedSarSat derives its window key with fold_in(key, 24). Resetting any of the four with PRNGKey(seed) therefore gives bit-identical orbits and targets. This is what makes the paired-seed comparison in §8 fair.

4. Core data elements

All environment data is stored in JAX NamedTuples with fixed shapes, so jit and vmap work over whole batches of environments. Shapes below use N for satellites, M for max_targets (padded), K for beam slots, H for the look-ahead horizon, C for hotspot clusters and T for time_limit.

State: what the simulator carries

FieldShapeMeaning
orbit (Orbit)5 × (N,)Circular-orbit elements: radius, mean_motion, inclination, raan, phase. They stay constant for the whole episode.
step() int32Steps taken so far. Position at time t is computed directly from the orbit, so nothing else about time is stored.
battery(N,)State of charge in [0, 1]. Sensing is allowed only while it holds at least sense_cost.
target_latlon, target_pos(M, 2), (M, 3)Target location in degrees and as an Earth-fixed position in km. Hotspot targets occupy the first hotspots × hotspot_targets slots.
target_priority(M,)Normalised to sum to 1. Padding slots are 0.
target_active(M,) boolTrue until the target is imaged. Padding slots are False.
target_window (windowed only)(M, 2) int32First and last step at which the target can be imaged.
cluster_access, team_future (Coop only)(T+H+1, N, C), (T+H+1, C)The whole episode's access schedule to each cluster centre, computed once at reset. team_future counts how many access opportunities to each cluster remain from each step on.
body, visible (Coop only)(N, M, 3), (N, M)Cached line of sight to every target at step + 1, which is the most expensive computation in the environment. refresh fills it, and both the observation and the next transition reuse it.

Action

The action is a (N, 4) float32 array, one row per satellite. The MAPX wrapper declares it as a hybrid action: one continuous block of size 2 and two binary blocks (action_spec).

[0] incidence ∈ [-1,1]
[1] squint ∈ [-1,1]
[2] side {0=L, 1=R}
[3] sense (>0.5)

Every action is legal. The incidence slot sweeps the accessible band from its inner edge to its outer edge, so a satellite can never point outside it. _encode_pointing is the exact inverse of the decoding: it turns a target's angles into the action that aims straight at it. Observations use this same encoding, so the pointing features of an observation slot are an action the agent can take directly.

Observation (what the policy sees)

CoopObservation has four fields: agents_view (N, obs_dim), action_mask (N, 4) (the sense slot is masked when the battery is too low), step_count (N,) and global_state (N, global_dim). Here is the layout of one satellite's row, with the sizes for sarsat-100sat-hotspots (K=4, H=16, C=40):

K × 8 beam slots (32)
H × 2 cluster look-ahead (32)
own (5)
agents_view (69)
team summary: 8 stats + C cluster fractions + H team look-ahead (64)
PartFeatures
Beam slot kvalid, incidence, squint, side, value, scarce_value, team_future, contention, plus window_left on windowed scenarios. The slots come from non-maximum suppression over the 64 most valuable accessible targets: slot 0 is the beam that captures the most priority (what greedy_beam would aim at), slot 1 is the best beam over what slot 0 leaves, and so on (_slots).
Look-aheadFor each of the next H steps, the value of the hotspot clusters this satellite will have access to, both raw and scarcity-weighted.
Ownbattery, can_sense, time_remaining, visible_value, visible_count.
Team summaryTime remaining, battery mean and quantiles, the fraction of satellites that can sense, remaining hotspot and background value, sorted cluster remaining fractions, and the team's mean look-ahead. It has a fixed size whatever N is: 133 numbers per agent here, where the joint observation would need 9,600.

TimeStep and reward

step returns a Jumanji TimeStep. Its reward has shape (N,) and holds the same team reward for every agent. discount becomes 0 only when every target has been imaged. The episode also ends (is truncated) at time_limit. transition_with_credit also returns each satellite's own share, credit (N,), where a target hit by several beams at once is split evenly. The training wrapper can blend this share into the reward (§7).

5. One environment step

A step is one fully vectorised pass over all satellite–target pairs. Time advances first, and the action is then applied at the new satellite positions. As a result, the first look-ahead slot of an observation describes exactly the geometry under which the action chosen from it will run (DECISIONS issue 6).

The complete transitionsarsat/env.py:291
def step(self, state: State, action: jax.Array) -> Tuple[State, TimeStep[Observation]]:
    step = state.step + 1
    _, sensing, in_beam = self._apply_action(state, step, action)
    imaged = jnp.any(in_beam, axis=0)  # (M,); a target pays once however many beams hit
    reward = jnp.sum(jnp.where(imaged, state.target_priority, 0.0))

    state = state._replace(
        step=step,
        battery=jnp.clip(
            state.battery + self.recharge_rate - self.sense_cost * sensing, 0.0, 1.0
        ),
        target_active=state.target_active & ~imaged,
    )
    ...  # TimeStep with the same reward for all N agents and observation self._observe(state)

CoopSarSat divides the same logic into pieces so that the training wrapper can put a reset between them. transition_with_credit computes the next state, the reward and each satellite's credit from the cached geometry. make_timestep then refreshes the cache for the next step and builds the observation.

Using the environment directlyREADME.md
import jax
from sarsat import SarSat

env = SarSat(num_satellites=8, max_targets=100)

Where experiments run

  • Local WSL2 (16 GB GPU). WSL2 caps any single allocation at about 4 GB, which is why num_envs is 32, 16 or 4. Run evaluations with JAX_PLATFORMS=cpu while a training job holds the GPU, and never put a third process on the GPU.
  • Runpod (A40 48 GB). The steps are in CLAUDE.md: ship the repo and MAPX to /workspace, install pinned versions with uv, then launch detached with nohup. The 500-satellite run used arch.num_envs=16 and ran at 259 env-steps/s. It plateaued around update 600 (about 2.2 h, $1.19). A saturated run is stopped early: after 20 evaluations, stop once the last 10 neither beat the earlier best by more than 0.005 nor average more than 0.003 above the previous 10.
Always pass exactly one seed. MAPX's default system.seed is a list of ten, so run.sh sets system.seed=42. Restoring a checkpoint requires the same arch.num_envs it was trained with.

7. How models are trained

Training uses MAPX's recurrent PPO systems in the fully jitted Anakin style: many environments are vmapped on one GPU, rolled out for a whole 180-step episode, and followed by a PPO update. Parameters are shared by all satellites, and the agents are interchangeable (implicit_agent_id: True).

The four ingredients that made learning work

DECISIONS issue 23 records the full history. In short:

  1. An observation you can act on. Each beam slot's pointing features are already in the action's own encoding, so copying slot 0 and sensing matches greedy_beam (scripts/coop_check.py checks this). The network only needs to learn when to depart from greedy.
  2. The slot-mixture head. SlotMixtureDistribution first chooses one of the K ranked slots, a latent choice that is marginalised out in log_prob, then samples a tanh-Gaussian around that slot's aim. Sensing is a separate masked Bernoulli. The head starts out biased towards slot 0 (slot0_bias=3), so "take the second-best beam because a teammate will take the best" costs one logit rather than a large pointing offset.
  3. Credit mixing. With the pure team reward, IPPO stalls at about 0.74. Blending in each satellite's own share lifts IPPO and MAPPO to 0.89–0.90 on the hotspot benchmark. The mean over agents is still the team reward:
Reward seen by the learnerwrappers/sarsat_coop.py:122
if self.credit_mix:
    # Blend the team reward with each satellite's own share of it (mean over agents
    # is still the team reward). Off by default: the task's reward is the team's.
    mixed = (1.0 - self.credit_mix) * reward + self.credit_mix * self.num_agents * credit
    timestep = timestep.replace(reward=mixed * self.reward_scale)
  1. Fused auto-reset. Under vmap, MAPX's AutoResetWrapper computes a full reset and an observation on every step. The wrapper instead resets inside step, before the observation is built. The next episode's expensive cluster schedule is built three rows per step while the current episode runs, and PassthroughAutoReset stands in for MAPX's wrapper. The eval env keeps the ordinary reset.

IPPO or MAPPO?

The two systems share the actor and differ only in the critic's input. The IPPO critic reads the agent's own agents_view. The MAPPO critic reads global_state, which is that view plus the fixed-size team summary. Because the summary does not grow with N, MAPPO stays affordable at 500 satellites. Both reached about 0.90 on the hotspot benchmark. MAPPO is the choice on the events benchmarks.

8. How evaluation is done

Evaluation happens at three levels. All of them report the same number: the fraction of priority imaged in one 180-step episode.

  1. During training. MAPX's evaluator runs greedy (mode) actions on the eval env every 30 updates and logs Fraction imaged mean. It keeps the best checkpoint, and the in-training learning curve comes from these results.
  2. Paired-seed test. The best checkpoint is replayed on the fixed test seeds 1000–1015 and compared seed by seed with reference policies on exactly the same orbits and targets.
  3. Diagnostics and visualisation. These tools show where a policy loses value and let you watch an episode on a map.

Reference policies (the yardsticks)

The reference policies are defined in sarsat/reference.py. They act from the full environment State, not from an observation, and share one interface, ReferenceController(env, state0, policy), which maps a state to an action. The planners first run precompute, which builds the whole episode's access table (T, N, M) and counts the remaining opportunities per target. lean_precompute builds the same tables in the smallest dtypes that hold them, which is needed at 200 and 500 satellites.

PolicyKnowsBehaviour
randomnothingUniform pointing; always asks to sense.
greedyits observationAims at observation slot 0 and senses if the target is accessible (greedy_policy).
greedy_beamitself, nowAims where its beam captures the most priority and senses whenever the battery allows. This is the fair independent baseline.
solo_planits own futureWeighs each target by how rarely this satellite will see it again, and rations looks to its battery budget.
coop_dedupeveryone, nowCentralised: never takes the same target twice in one step.
coop_planeveryone's futureCentralised: deduplicates, weights scarcity by every satellite's future access, and respects each look budget. This is the cooperative reference.

Measuring a scenario before training on it

Scenario design is an experiment in its own right. It asks how much cooperation is worth before any model is trained. cooperation_gap.py runs the reference policies on one configuration, and scenario_sweep.py runs them over a table of candidate configurations. The gap between coop_plan and the better independent policy is the headroom a coordinating learner could capture. That is how the events benchmarks were chosen (DECISIONS issues 22, 24 and 26).

run_episode(env, policy, seed) accepts three kinds of policy: the name of a reference policy, a pure function Observation → action (which it jits), or a stateful object with reset() and __call__, such as a recurrent actor. It returns an EpisodeLog. To try the viewer, open sarsat/viewer.html and drop in the CSVs from any folder in examples/.

Running the actor live

sarsat.live.LiveWorld turns the episodic environment into rolling episodes so the trained 500-satellite actor can run forever: every 180 steps the world (orbits re-based, batteries carried over, background respawned, fresh events) is re-packed into a fresh state and the actor's GRU carry is reset, so the policy always sees its training distribution. A request takes over a closed event cluster as 50 co-located slots with a window of at most 30 steps. tests/test_live.py pins episode 0 to env.reset + env.step. The browser demo that drives it at 60x real time (server, web UI, msgpack snapshot loader, offline natural-language parser) is a separate repository, sarsat-live, which pins a sarsat release. 10. Glossary

TermMeaning
Incidence / look angleIncidence is the angle at the target between the line of sight and the local vertical. The look angle is the same idea measured at the satellite from nadir, and is always the smaller of the two. The sensor can image only within an incidence band.
SquintThe along-track angle away from broadside, limited to ±25°.
Body frameEach satellite's axes: along (direction of flight), cross, nadir. Azimuth is measured cross-track and elevation along-track.
Duty cyclerecharge_rate / sense_cost: the fraction of steps a satellite can sustain sensing on.
Hotspot / clusterA Gaussian cluster of high-priority targets (×10) centred on land.
Event / windowA hotspot cluster that can be imaged only during one 10–30-step window.
Walker planesplanes > 0: satellites spread evenly within each orbital plane. train_spacing_s turns them into formation pairs or trains.
ContentionA slot feature: how many charged teammates can see the same target at the same step. With ranked_contention, only teammates with a lower index are counted.
credit_mixThe weight given to each satellite's own share when it is blended into the team reward. Training only; evaluation always uses the team reward.
AnakinMAPX's single-device, fully jitted architecture, in which environment and learner run together on the GPU.
Paired seedsSeeds 1000–1015. Every policy is scored on the same orbits and targets for each seed, so per-seed differences are meaningful.
